## How a target is decided

Nothing here inspects the picture on screen. A target is decided from two different kinds of evidence the port emits while it plays:

1. **Probes.** A `coverage_hit("name")` call sits inside the translated routine, at the exact branch where the event happens. It proves the port *executed that path* — not that a button was pressed. `two_player_turn_switch`, for instance, only fires on the branch that hands play back from player two, and only when `GameOrAttract == 0x02`, so the attract demo cannot satisfy it.
2. **Frame sampling.** `coverage_observe_frame()` runs once per frame and reads the game state, producing counters such as `mothership_gameplay_frames`. Some values are derived rather than probed: `player_deaths` is *game state changed to 4*, `level_transitions` is *LevelAndRound changed*.

A probe proves the code went there; a frame counter proves the state existed. Both are written to the file named by `--coverage-dump=`, and the conditions below read that file.

This measures the **C port**. That the original ROM takes the same branch is not shown here — that is what the lockstep comparison is for. It also means a new target cannot be invented from the outside: it needs a probe in the C source or a counter in the sampler first.

## Starting a game and two-player mode

| Target | What it means | Condition in the code | Measured in |
| --- | --- | --- | --- |
| `coin_accepted` | A coin was accepted. The shortest possible check that input reaches the machine at all. | `hit(c, "coin_accepted")` | `attract_mode.c` → `decrement_coins()` |
| `player_2_bank_initialized` | Player two's separate RAM bank was set up. Proves the port keeps two independent game states, not one. | `hit(c, "player_2_bank_initialized")` | `attract_mode.c` → `prompt_for_start_game()` |
| `two_player_game_started` | A two-player game was started. Only says the game began, not that both players actually played. | `hit(c, "two_player_game_started")` | `attract_mode.c` → `decrement_coins()` |
| `two_player_turn_switch` | Play actually handed over from one player to the other. This is the real two-player test; the two above are its preconditions. | `hit(c, "two_player_turn_switch")` | `game_state_machine.c` → `state_0_new_game_start()` |

## The player: shooting, shield, dying

| Target | What it means | Condition in the code | Measured in |
| --- | --- | --- | --- |
| `enemy_bullets_active` | Enemy fire was in the air. Distinct from the player dying: it only means the enemy shot back. | `summary(c, "enemy_bullet_active_frames") > 0` | per-frame sampler in `coverage.c` |
| `game_over` | All lives were lost and the game ended. Use this, not player_death, when you need the ending sequence itself. | `summary(c, "game_overs") > 0` | per-frame sampler in `coverage.c` |
| `player_bullet_fired` | The player fired at least one shot. A smoke test: if this misses, the replay never got out of the attract screen. | `hit(c, "spawn_player_bullet")` | `player_logic.c` → `spawn_player_bullet()` |
| `player_death` | The player lost a life. One life - the game may well continue afterwards. | `summary(c, "player_deaths") > 0 or hit(c, "player_killed")` | per-frame sampler in `coverage.c`, `weapon_collision.c` → `l0cc4_player_killed()` |
| `shield_used` | The shield button was pressed. Needed for anything that studies the 4x4 shield sprite or its collision handling. | `hit(c, "player_shield_pressed")` | `player_logic.c` → `move_player()` |

| `grown_bird_bonus_explosion` | A fully grown bird was destroyed and paid its bonus. The narrow counterpart of bird_hit. | `hit(c, "grown_bird_bonus_explosion")` | `collision_detection.c` → `l3844_small_bird_hit()` |

## Command-line options

### `input_bot.py evaluate`

| Option | Default | What it does |
| --- | --- | --- |
| `--script` | required | input script to replay |
| `--frames` | `8000` | frames to run |
| `--emulator` | `./build/c-phoenix` | emulator binary |
| `--cwd` | `.` | working directory for emulator |
| `--coverage-out` | required | write/read coverage JSON at this path |
| `--ram-dump` | required | optional RAM dump output path |
| `--sdl-video-driver` | required | optional SDL_VIDEODRIVER override |
| `--no-render` | flag | skip rendering during headless runs |
| `--json` | flag | print raw coverage JSON |
| `--target` | `[]` | target to evaluate; can be repeated |

### `input_bot.py list-targets`

| Option | Default | What it does |
| --- | --- | --- |
| `--plain` | flag | print bare target names only, one per line, for scripting |

### `input_bot.py mutate`

| Option | Default | What it does |
| --- | --- | --- |
| `--seed` | required | seed input script |
| `--frames` | `8000` | frames to run each candidate |
| `--iterations` | `20` | number of candidates per generation |
| `--generations` | `1` | rounds of search; each round re-seeds with the previous round's best script, so the search climbs instead of resampling the same seed (default 1 = a single flat round) |
| `--keep` | `5` | number of top scripts to save |
| `--output-dir` | `/tmp/input-bot` | where to save the top scripts (default: a scratch directory; promoting a script into context/input-scripts/generated is a deliberate step, taken only after evaluate has confirmed it) |
| `--force` | flag | allow replacing existing files in --output-dir |
| `--emulator` | `./build/c-phoenix` | emulator binary |
| `--cwd` | `.` | working directory for emulator |
| `--sdl-video-driver` | `dummy` | SDL_VIDEODRIVER for emulator |
| `--random-seed` | `1` | deterministic RNG seed |
| `--mutate-after` | `220` | preserve seed events before this frame |
| `--mutation-mode` | `regenerate` | how to mutate events after --mutate-after |
| `--verbose` | flag | print emulator output on failures |
| `--target` | `[]` | target to reward; can be repeated |
